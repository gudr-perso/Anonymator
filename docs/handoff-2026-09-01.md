## Décisions prises (ne pas les rejouer)

1. **arm64 uniquement.** PyTorch ne publie plus de wheels macOS x86_64 depuis la
   2.3 ; les Mac Intel sont hors périmètre. `universal2` est hors d'atteinte pour
   la même raison. Cible : macOS 11+ sur puce Apple.
2. **Pas de notarisation Apple** (99 $/an non justifiés pour une diffusion
   restreinte). Conséquence assumée : Gatekeeper bloquera le `.app` dès qu'il aura
   été transféré. La procédure de déblocage (`xattr -dr com.apple.quarantine`)
   voyage **avec l'app** : `build.sh` écrit un `LISEZ-MOI.txt` à la racine de
   l'archive, rédigé pour une utilisatrice non développeuse.
   Seuil de bascule vers la notarisation : si la diffusion dépasse quelques personnes.
3. **`.venv` recréé sur place**, et non déplacé hors de pCloud : l'exclusion pCloud
   a été faite côté client, ce qui traite la cause racine sans changer les chemins
   de toutes les commandes. Validé — zéro nouveau fichier `(conflicted)`.
4. **CI en Python 3.14**, aligné sur le poste de dev. Si une wheel macOS arm64
   manque pour cp314 (PySide6 est le candidat le plus probable), se rabattre sur
   `3.12` dans le workflow.
5. **Aucune valeur recopiée en dur** dans `build.sh` : version, taille du modèle
   (`MODEL_DOWNLOAD_SIZE`) et noms de marques (`BRANDS` de `anonymator/brand.py`)
   sont tous dérivés du code. Ce projet a déjà été mordu par un libellé figé qui
   avait divergé (cf. `anonymator/core/model_status.py:14`).

## Prochaine tâche immédiate : lancer le PoC macOS

Le workflow est sur `main`, donc visible dans l'onglet **Actions** de
https://github.com/gudr-perso/Anonymator.

1. Actions → `build-macos` → **Run workflow** → choisir la marque (`cap` par défaut).
2. Durée attendue : 20–40 min (installation de torch + PySide6, puis gel).
3. Le workflow contient un **smoke test** : il lance chaque binaire gelé en mode
   offscreen et échoue s'il ne survit pas 30 s. C'est là que sortiront les vraies
   surprises (dylib manquante, plugin Qt absent).
4. Récupérer l'artefact `anonymator-macos-arm64` en bas de la page du run.

### Si ça échoue

- **Wheel manquante à l'installation** → passer `python-version` de `'3.14'` à
  `'3.12'` dans le workflow (commentaire déjà en place).
- **Le smoke test tue le run** → lire les logs de l'étape « Smoke test des
  bundles ». Cause la plus fréquente : un import manquant dans `hiddenimports`
  du `.spec`, ou un plugin Qt non embarqué.
- **`make_icns.sh` échoue** → vérifier que `anonymator/ui/assets/picto.png` existe.
  Il fait 512×512 ; le slot `512x512@2x` (1024 px) est volontairement omis.

## Pièges connus

- **PowerShell 5.1** : ne jamais ajouter `2>&1` sur une commande native (PyInstaller) —
  chaque ligne de stderr devient une `NativeCommandError` et `$?` passe à faux même
  avec un code retour 0.
- **`build/` contient 20 fichiers `(conflicted)` datant du 8 juillet.** Vestiges
  d'un ancien conflit pCloud, sans effet sur les builds actuels, mais susceptibles
  de perturber un build incrémental. Le dossier est un cache : supprimable sans risque.
- **`ditto`, pas `zip`**, pour archiver un `.app` : les frameworks Qt contiennent des
  liens symboliques et une signature ad-hoc que `zip` détruit.
- **Ne rien écrire *dans* le `.app` après le build** : cela invalide sa signature.
  `LICENSE`, `LISEZ-MOI.txt` et `exemples/` vont **à côté** du bundle.
